# Italian (it) — translator notes

- **Register**: informal "tu" throughout, which is normal for Italian tech and launch pages. I kept sentences short and dropped repetition where the English loops back on itself (e.g. `time.lead` ends "…it doesn't change the time" a second time; the Italian says it once).
- **Unit names**: gong, kè, beat and tic are all masculine (il gong, il kè, il beat, il tic). As loanwords they don't change in the plural, so `units.gongs/beats/ticks/kes` are the same as the singulars. That is correct Italian, not an oversight.
- **"gong:beat:tick" in `how.lead`**: I left it in English, following the brief's "never alter" rule for readout patterns. Everywhere else the unit is "tic", so Italian readers see both "tick" and "tic". If the clock's readout label is translatable, I'd change this to `gong:beat:tic` to match.
- **`ke.facts[2..3].n` = "Longitude" / "Latitude"**: these stay in English because the checker treats every `n` field as verbatim. They show up on the page as labels, so Italian readers will see English words. They should be "Longitudine" / "Latitudine". The fix is to exempt these two from the verbatim check, or move them to a translatable key.
- **Prime Meridian (Greenwich)** → "meridiano di Greenwich", the standard Italian term. "Meridiano fondamentale di Greenwich" would be redundant.
- **Title "time and location reimagined"** → "tempo e luogo, ripensati". "Reimmaginati" is a calque, and "reinventati" sounds like hype. "Ripensati" is confident but plain. The nav and section headings use "Il tempo, ripensato".
- **"Why now" / "It's time."** → "Perché adesso." / "È ora." The pun carries over naturally ("è ora" means both "it's time" and "it's the hour").
- **"Your place in the sun"** → "Il tuo posto al sole", an existing Italian idiom, so the wordplay survives. I rendered "sun overhead" as "il punto più alto del cielo" because "zenit" would be wrong outside the tropics.
- **Numbers**: running text uses Italian grouping (1.000, 100.000, 86.400). The tables (geometry, trig, quartz) keep the English values as the brief requires. That causes a real ambiguity: Italians read "16.67 kè" as sixteen thousand and "28,311" as a decimal. The quartz note "(28,311 / 28,312)" is the worst case. If tables can be localised later, Italian should use "16,67" and "28.311".
- **sin/cos/tan**: Italian schools traditionally write "sen" and "tg". I kept sin/cos/tan, which match calculators, software and the table values. It is a judgment call.
- **AM/PM**: Italians use the 24-hour clock and don't really use AM/PM. I kept the joke list as written ("AM e PM" is widely recognised), but this item lands less well in Italy.
- **Join form roles**: "I am a…" plus masculine job titles would force a gender on the reader. I used "Profilo" with field-of-work options (Sviluppo software, Ricerca / università, Semplice curiosità…). The success message "Ti diamo il benvenuto" avoids "Benvenuto/a" for the same reason.
- **Glossary terms**: Daylight Saving → "ora legale"; leap seconds → "secondi intercalari"; International Date Line → "linea del cambio di data"; standards bodies → "enti di normazione"; Gēng night watches → "veglie".
- **China "standards" card**: I kept "National Time Service Center" in English as a proper name (there is no settled Italian name) and kept claims exactly as strong as the source. The English heading "are being re-written in 2035" is vague; "si riscrivono entro il 2035" is my best reading, and the source should be checked.
- **Cities**: I used standard exonyms (Pechino, Londra, Mosca, Giacarta, Seul, Riad, San Paolo, Città del Messico, Città del Capo, Il Cairo, Bogotà, Stoccolma, Barcellona). "Santiago" became "Santiago del Cile" to rule out Compostela. "New York City" became "New York". The licence/patent sentence in `build.license` is legal text and should get a quick legal review.
